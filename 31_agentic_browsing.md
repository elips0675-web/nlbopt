# 31. Agentic Browsing — что это и почему 1/2

**Актуально на 26.10.2026.** Lighthouse **13.3**, Chrome 150+, мобильная эмуляция.

Agentic Browsing — новая экспериментальная категория Lighthouse (v13.3, май 2026). Она проверяет, насколько сайт пригоден для взаимодействия с AI-агентами: читается ли дерево доступности, не прыгает ли вёрстка, есть ли `llms.txt`, объявлены ли WebMCP-инструменты.

Категория **не имеет балла 0–100**. Она показывает дробь — сколько проверок пройдено из применимых. У nlb сейчас **1/2**.

---

## Как считается

В категории шесть аудитов, но на обычном Chrome без origin trial работают три:

| Аудит | Что проверяет | У нас |
|---|---|---|
| `agent-accessibility-tree` | 38 правил axe: имена кнопок/ссылок, label у полей, валидность ARIA, tabindex, autocomplete | ❌ провал |
| `cumulative-layout-shift` | CLS — стабильность макета | ✅ 0 |
| `llms-txt` | Формат файла `llms.txt` (не наличие) | N/A |
| `webmcp-form-coverage` | Формы без `toolname` / `tooldescription` | N/A |
| `webmcp-registered-tools` | Какие WebMCP-инструменты зарегистрированы | N/A |
| `webmcp-schema-validity` | Валидность JSON Schema инструментов | N/A |

Три WebMCP-аудита возвращают N/A, пока сайт не зарегистрирован в origin trial. Остаётся три проверки, но у нас в знаменателе две: `llms.txt` не применим, потому что файла нет.

**Почему 1/2, а не 1/3.** `llms.txt` попадает в знаменатель только если файл реально отдаётся. Сейчас `/llms.txt` возвращает **403** — в прогоне это ушло в N/A, а не в fail. Провалена одна проверка из двух — accessibility tree. CLS 0, поэтому она проходит.

**Осторожно с `llms.txt`.** Правила жёсткие:

| Ситуация | Результат |
|---|---|
| `/llms.txt` отсутствует (404; на nlb сервер отвечает 403) | N/A, проверка выпадает из знаменателя |
| Файл загружен, но сервер отдаёт 403/500 | ❌ 0 (server error) |
| Файл отдаётся, формат битый | ❌ 0 |
| Файл отдаётся, формат корректный | ✅ |

То есть **битый файл хуже отсутствующего**. Сначала чините отдачу `.txt`, потом публикуйте.

## 1. Accessibility tree — единственный реальный провал

Агенты не видят CSS. Они читают страницу тремя способами: скриншот, HTML и дерево доступности. Дерево — основной источник: по нему агент понимает, что кликабельно, как называется кнопка и куда ведёт ссылка.

`agent-accessibility-tree` — это набор из 38 правил axe. **Одно нарушение на странице — и аудит в нуле**, частичных баллов нет.

У nlb провал тот же, что и в обычной доступности (A11y 83):

- **3 ссылки без доступного имени** — вероятно иконки соцсетей в футере и стрелки слайдера;
- часть кнопок/иконок без `aria-label`;
- у части изображений `alt=" "` вместо осмысленного текста или пустого `alt=""`.

Важно: `color-contrast` и `target-size` — проверки для людей, в agent-tree они не входят. Поэтому A11y 83 и Agentic 1/2 — разные вещи, но чинятся одним набором правок.

### Что делать

Иконка-ссылка:

```html
<a href="https://vk.com/nlb_by" aria-label="ВКонтакте">
    <svg aria-hidden="true" focusable="false">...</svg>
</a>
```

Кнопка-стрелка слайдера:

```html
<button type="button" class="slider-prev" aria-label="Предыдущий слайд">
    <svg aria-hidden="true">...</svg>
</button>
```

Поле поиска:

```html
<label for="site-search" class="visually-hidden">Поиск по сайту</label>
<input id="site-search" type="search" name="q" autocomplete="off">
```

Правила:

- кликабельное — `<a>` или `<button>`, не `<div>` с `onclick`;
- у каждого интерактивного элемента есть текст или `aria-label`;
- декоративные картинки — `alt=""` (без пробела), смысловые — нормальный `alt`;
- у полей — `<label for>`, placeholder не считается;
- `autocomplete` — по спецификации (`name`, `email`, `tel`), иначе аудит ругается.

Проверять: axe DevTools → те же нарушения, что в Lighthouse, но с подсветкой элементов. Полный список правок — в `30_seo_meta_a11y.md`, разделы 6–8.

После этого Agentic станет **2/2** (a11y tree + CLS).

## 2. CLS — уже 0

Проверка проходит. Для агента это важно не меньше, чем для человека: если кнопка уезжает, агент кликает мимо.

Трогать ничего не нужно. Главное — не сломать:

- у картинок и iframe остаются размеры или `aspect-ratio`;
- баннеры не вставляются над уже отрисованным контентом;
- шрифты не меняются без `font-display: swap` и preload.

Подробности — `01_lazy_load_images.md`.

## 3. `llms.txt` — опционально, но с оговорками

`llms.txt` — предложенный формат: Markdown-файл в корне сайта, который кратко описывает сайт и даёт ссылки на ключевые разделы. Идея в том, чтобы агент не ползал по 37 тысячам URL из sitemap, а сразу понял структуру.

Честно о пользе:

- Google Search **игнорирует** `llms.txt` — это официальная позиция;
- крупные исследования показывают, что большинство таких файлов не приносят трафика;
- для AI-краулеров это не robots.txt и не способ запретить обучение.

Но Lighthouse проверяет формат, и если файл есть, он должен быть корректным. Плюс это дешёво: полчаса работы.

### Формат

Три обязательных условия:

1. Markdown-заголовок H1: строка `# Название`;
2. минимум одна ссылка в формате `[текст](https://...)` — голые URL и просто список пунктов не считаются;
3. больше 50 символов.

### Готовый файл для nlb

Положить в корень сайта: `https://www.nlb.by/llms.txt`. Пути проверить и заменить на реальные разделы.

```markdown
# Национальная библиотека Беларуси

> Национальная библиотека Беларуси — крупнейшая библиотека страны. Электронный каталог, электронная библиотека, новости, выставки и экскурсии, обзорная площадка. Минск, пр. Независимости, 116.

## Основное

- [Главная страница](https://www.nlb.by/): новости, анонсы, быстрые ссылки.
- [Новости](https://www.nlb.by/content/news/): события и объявления библиотеки.
- [Электронный каталог](https://www.nlb.by/): поиск по фондам библиотеки.
- [Электронная библиотека](https://elib.nlb.by/): цифровые коллекции и полнотекстовые документы.

## Языковые версии

- [Беларуская версія](https://www.nlb.by/by/)
- [English version](https://www.nlb.by/en/)

## О библиотеке

- [История и миссия](https://www.nlb.by/about/): сведения о библиотеке.
- [Контакты и часы работы](https://www.nlb.by/contacts/): адрес, режим работы, телефоны.
```

Требования к содержимому: только публичные страницы, без `/bitrix/`, `/upload/`, `/adminer.php`; ссылки — на канонический хост (`www`, если выбран он); описание — 1–2 предложения, без маркетинга.

`llms-full.txt` (полная версия) делать не обязательно — Lighthouse его не проверяет.

### Сначала починить 403

Сейчас сервер отдаёт **403 на любой `.txt`, кроме `robots.txt`**. Проверено: `/llms.txt`, `/humans.txt`, `/security.txt`, `/ads.txt` — все 403. Это не nginx, а Apache (страница ошибки Apache), значит запрет где-то в `.htaccess` или в настройках безопасности.

Найти правило:

```bash
grep -rn --include=".htaccess" -E "\.txt|FilesMatch|Require all denied" /var/www/nlb.by/
```

Типовые причины:

```apache
# кто-то закрыл все .txt, кроме robots
<FilesMatch "\.txt$">
    Require all denied
</FilesMatch>
```

Исправление — разрешить конкретный файл **после** общего запрета:

```apache
<Files "llms.txt">
    Require all granted
</Files>
```

Если стоит `FilesMatch` с отрицанием, можно так:

```apache
<FilesMatch "^(?!robots\.txt$|llms\.txt$).*\.txt$">
    Require all denied
</FilesMatch>
```

Если перед Apache есть nginx, проверить и его:

```nginx
location = /llms.txt {
    try_files $uri =404;
}
```

Порядок:

1. Починить отдачу `.txt` — `curl -I https://www.nlb.by/llms.txt` должен вернуть **200**, а не 403.
2. Только потом загружать файл. Если оставить 403 при существующем файле — будет fail, а не N/A.
3. Проверить содержимое:

```bash
curl -s https://www.nlb.by/llms.txt | head -5
curl -s https://www.nlb.by/llms.txt | grep -cE '^# .+'
curl -s https://www.nlb.by/llms.txt | grep -cE '\[.+\]\(.+\)'
```

Content-Type: `text/plain; charset=utf-8` или `text/markdown; charset=utf-8` — оба нормально.

После публикации знаменатель станет 3, и при корректном формате будет **3/3**.

## 4. WebMCP — пока не трогать

WebMCP — API, которым сайт объявляет агенту свои действия прямо в браузерной сессии: «найди книгу», «запиши на экскурсию», «проверь наличие». Есть декларативный вариант (атрибуты на формах) и императивный (`navigator.modelContext.registerTool`).

Статус на 26.10.2026: **origin trial Chrome 149–156**, то есть эксперимент, а не стандарт. Без регистрации в trial все три WebMCP-аудита возвращают N/A — на дробь они не влияют.

Для балла делать не нужно. Если появится задача «пусть агенты умеют искать по каталогу», начинать с декларативной разметки формы:

```html
<form toolname="search_catalog"
      tooldescription="Поиск книги или статьи по электронному каталогу библиотеки">
    <label for="q">Запрос</label>
    <input id="q" name="q" type="search" required>
    <button type="submit">Найти</button>
</form>
```

Императивный вариант и JSON Schema — только после того, как API выйдет из trial. Следить за статусом: `developer.chrome.com/docs/ai/webmcp`.

## 5. Как проверить

```bash
# только Agentic Browsing, с открытием отчёта
npx lighthouse https://nlb.by/ --only-categories=agentic-browsing --view

# JSON для CI
npx lighthouse https://nlb.by/ --only-categories=agentic-browsing \
  --output=json --output-path=./agentic.json
```

Требования: Lighthouse 13.3+, Chrome 150+. В PageSpeed Insights категория появляется автоматически. В DevTools — вкладка Lighthouse, галочка Agentic Browsing.

Что смотреть в отчёте:

- `agent-accessibility-tree` — список конкретных элементов с нарушениями;
- `cumulative-layout-shift` — значение CLS;
- `llms-txt` — N/A / pass / fail и причину.

## 6. Что это даёт и чего не даёт

Даёт:

- **2/2** после починки имён ссылок и кнопок — это же поднимает A11y с 83;
- **3/3** после корректного `llms.txt`;
- понятный чек-лист: семантика, имена, стабильность. Всё это полезно и людям.

Не даёт:

- трафика. Нет доказанной связи между дробью и AI-переходами;
- влияния на обычный SEO — Google Search `llms.txt` не читает;
- замены robots.txt или способа запретить обучение.

Относиться как к гигиене, а не как к KPI. Категория помечена Google как экспериментальная и небенчмарковая.

---

## Приоритет

1. **Доступные имена ссылок и кнопок** — 1–2 часа, 1/2 → 2/2 и A11y 83 → 90+. Самый большой эффект.
2. **Починить 403 на `.txt`** — 15 минут, без этого `llms.txt` публиковать нельзя.
3. **`llms.txt` по формату** — 30 минут, 2/2 → 3/3.
4. **WebMCP** — не делать до выхода из origin trial.
